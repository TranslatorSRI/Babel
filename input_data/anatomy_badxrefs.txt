# Individually wrong cross-reference pairs to drop from the anatomy concords.
#
# Format: "SUBJECT OBJECT", space separated, one pair per line, "#" comments. Matched in EITHER
# direction, so the orientation a concord happens to write does not matter.
#
# This file is for pairs that survive prefix-level filtering (ANATOMY_OBO_IGNORE_LIST) because the
# target prefix is legitimate in general -- MESH and GO really are anatomy xref targets -- but this
# particular pair is wrong. Prefer fixing upstream where possible; each entry here is a standing
# assertion that an ontology's own xref is incorrect, so state the reason.
#
# The characteristic symptom is a clique whose members disagree about what kind of thing they are:
# a cell type merged with the gross structure it sits in, or an anatomical structure merged with a
# cellular component. Those show up as identifiers landing in an unexpected compendium
# (Cell.txt / CellularComponent.txt), which is a cheap thing to scan for after a build.

# UBERON:0001236 "adrenal medulla" hasDbXref MESH:D019439, which is "Chromaffin Cells" -- the cell
# type found in the adrenal medulla, not the medulla itself. This one xref welded the chromaffin
# cell clique (CL:0000166) to the adrenal medulla clique (UBERON:0001236), producing a
# biolink:Cell clique that also claimed to be the gross structure. UBERON reaches the correct MeSH
# term (D000313 "Adrenal Medulla") independently via UMLS:C0001629, so nothing is lost by dropping
# this pair.
UBERON:0001236 MESH:D019439

# UMLS:C0008503 "Chorion" is equated to GO:0042600 "egg chorion" in the UMLS concord. The GO term
# is a cellular component (the acellular envelope of an insect/fish egg); the UMLS concept is the
# mammalian extraembryonic membrane. This merged UBERON:0003124 "chorion membrane" into a
# biolink:CellularComponent clique.
UMLS:C0008503 GO:0042600

# UBERON:0000125 "neural nucleus" (a cluster of neuron cell bodies in the CNS) hasDbXref
# NCIT:C13197, which is the cell nucleus (NCIT synonym "Cell Nucleus", UMLS CUI C0007610). The
# UMLS concord then correctly ties NCIT:C13197 to UMLS:C0007610, MESH:D002467 "Cell Nucleus" and
# FMA:63840, so this one xref merged the neural nucleus with the whole cell-nucleus clique (and,
# once UMLS-GO mappings are used for anatomy, with GO:0005634 "nucleus").
UBERON:0000125 NCIT:C13197

# UBERON:0012456 "Merkel nerve ending" hasDbXref MESH:D018862, which is "Merkel Cells" (UMLS:C0205832)
# -- the epithelial cell, not the nerve ending (the Merkel cell together with its afferent terminal,
# FMA:83606 "Merkel's disc"). This one xref welded the nerve ending into the CL:0000242 "Merkel cell"
# clique, so once UBERON's SNOMED xrefs join, UMLS:C0228104 "Merkel's Corpuscle" followed it there too.
# UBERON's own FMA and SNOMED xrefs (FMA:83606, SNOMEDCT:9317004) already reach the correct concept.
UBERON:0012456 MESH:D018862

# UBERON:0008883 "osteoid" hasDbXref FMA:66830, which is "Bone matrix" -- osteoid is only the
# unmineralized organic part of bone matrix. Once UBERON's FMA xrefs are used, this merged osteoid with
# UMLS:C0005962 "Bone Matrix" and MESH:D001857.
UBERON:0008883 FMA:66830

# UBERON:0003691 "epidural space" hasDbXref FMA:71228, which is "Cranial epidural space", a narrower
# term (FMA also has FMA:71230 "Spinal epidural space"). Once UBERON's FMA xrefs are used, this merged
# the general epidural space with UMLS:C0228133 "Cranial epidural space".
UBERON:0003691 FMA:71228

# UBERON:0002464 "nerve trunk" hasDbXref SCTID:281248001, which is "Structure of nervous system of trunk"
# -- the nervous system of the body's trunk, not a nerve trunk. Listed with Babel's SNOMEDCT spelling
# because config.yaml: anatomy_xref_prefixes renames SCTID before this filter applies. Once UBERON's
# SNOMED xrefs join, this merged UMLS:C0460042 into the nerve trunk clique.
UBERON:0002464 SNOMEDCT:281248001
